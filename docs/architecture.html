🔑 Keystone：單執行緒 FFmpeg core

app.js:1068 明確寫下這個取捨：用單執行緒 core 換取「不需要 SharedArrayBuffer / COOP-COEP header」。 這一個技術決定同時支撐了 README 的兩個賣點——「完全本地處理，資料不上傳」與「純 HTML/CSS/JS，簡單部署」—— 因為不需要伺服器端設定跨來源隔離 header，可以直接丟上 GitHub Pages 這類最陽春的靜態主機。

無後端由此而生

因為壓縮運算本身就在瀏覽器內完成，這個專案天生就不需要 API 層、資料庫、佇列或 Worker。 唯二對外連線是 GitHub Pages（託管靜態檔案本身）與 Google Fonts CDN（字型），皆與影片資料無關。

代價：效能與檔案大小上限

單執行緒放棄了多執行緒加速，壓縮速度較慢；HANDOFF.md 記錄大檔案（>500MB）可能導致瀏覽器記憶體不足（OOM）， 這是架構代價，非程式錯誤。
